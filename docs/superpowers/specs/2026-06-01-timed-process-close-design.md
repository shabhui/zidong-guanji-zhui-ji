# 进程退出触发：定时关闭被监控程序设计

## 背景

AutoShutdown 已有“进程退出触发”：用户从当前进程列表选择一个程序，开始监控后，只有当该程序曾经出现过、随后同名进程数量变成 0 时，才进入现有提醒流程并执行当前电源动作。

本次功能是在这个现有触发器上增加“定时关闭被监控程序”。典型场景是：用户运行一个监控/下载/录制类程序，AutoShutdown 监控它；到设定时间后 AutoShutdown 先关闭该程序，程序退出后复用已有进程退出触发逻辑执行关机、睡眠、锁定等动作。

## 目标

- 在现有“进程退出触发”卡片中增加自动关闭被监控程序的设置。
- 用户开始监控进程时，可同时启动一个关闭倒计时。
- 倒计时到点后，AutoShutdown 尝试关闭被监控程序。
- 被监控程序退出后，仍由现有 `ProcessExitService.ProcessExited` 路径触发当前电源动作提醒流程。
- 停止进程监控时，也停止自动关闭倒计时和相关状态显示。

## 非目标

- 不新增独立的“定时关闭程序”任务中心类型。
- 不把该功能加入保存任务列表。
- 不改变网络闲置触发、普通倒计时、指定时间计划的行为。
- 不跳过现有提醒弹窗直接执行电源动作。

## 用户体验

在“进程退出触发”卡片中保留现有进程列表和开始/停止按钮，并新增：

- 一个可编辑的进程下拉框（WPF `ComboBox IsEditable=True`）：下拉项来自当前进程列表，也允许手动输入当前未运行的程序名。
- “自动关闭被监控程序”开关。
- 关闭倒计时输入：小时、分钟、秒。
- 关闭超时秒数输入，默认 10 秒。
- 状态文本显示：
  - 等待进程出现。
  - 正在监控进程实例数量。
  - 自动关闭倒计时剩余时间。
  - 正在尝试关闭程序。
  - 程序已退出，已触发任务。

默认建议值：

- 自动关闭关闭：默认关闭。
- 关闭倒计时：默认 1 小时。
- 关闭超时：默认 10 秒。

## 行为流程

1. 用户选择或输入进程名，例如 `MonitorApp` 或 `MonitorApp.exe`。
2. 用户可打开“自动关闭被监控程序”，并设置关闭倒计时。
3. 用户点击“开始监控进程退出”。
4. `ProcessExitService` 开始监控归一化后的进程名。
5. 如果自动关闭已打开，新的定时关闭服务同时开始倒计时。
6. 倒计时期间，状态文本显示进程状态和自动关闭剩余时间。
7. 倒计时到点后：
   - 查找同名进程。
   - 对有主窗口的实例调用正常关闭。
   - 等待最多 N 秒。
   - 仍未退出的实例强制结束。
8. 自动关闭服务只负责让程序退出，不直接执行电源动作。
9. `ProcessExitService` 检测到该进程曾出现过且数量变为 0 后，触发现有 `ProcessExited` 事件。
10. `MainWindow.OnProcessExited` 继续执行现有流程：停止监控、设置单次规则、重置提醒标记、用提醒秒数启动倒计时、更新状态 UI。

## 边界和错误处理

- 程序名为空：不启动监控，状态提示用户先选择或输入程序名。
- 自动关闭开启但关闭倒计时为 0：不启动监控，状态提示倒计时必须大于 0。
- 程序名带 `.exe`：归一化为不带扩展名的进程名。
- 到点时未找到目标进程：自动关闭服务显示“未找到进程”，不直接触发电源动作；如果该进程从未出现过，现有进程退出触发不会误触发。
- 目标进程没有主窗口：跳过正常关闭，进入超时后强制结束阶段。
- 部分进程关闭失败：记录失败数量到状态文本或托盘提示；仍依赖 `ProcessExitService` 判断是否真的变成 0 个实例。
- 用户点击“停止监控”：停止 `ProcessExitService`，同时停止自动关闭倒计时。

## 组件设计

### AppSettings

新增设置字段：

- `ProcessTriggerAutoCloseEnabled`：是否启用自动关闭被监控程序。
- `ProcessTriggerCloseHours`：关闭倒计时小时。
- `ProcessTriggerCloseMinutes`：关闭倒计时分钟。
- `ProcessTriggerCloseSeconds`：关闭倒计时秒。
- `ProcessTriggerCloseTimeoutSeconds`：正常关闭等待超时秒数。
- `ProcessTriggerProcessName`：最近一次输入/选择的进程名。

### TimedProcessCloseService

新增服务，职责单一：管理“到点关闭某进程”。

接口建议：

- `Start(processName, delay, timeoutSeconds)`：开始倒计时。
- `Stop()`：停止倒计时。
- `Tick` 事件：通知剩余时间。
- `Closing` 事件：通知正在关闭。
- `Completed` 事件：通知关闭尝试完成及统计信息。

实现要点：

- 使用 1 秒 `System.Timers.Timer` 封装倒计时，与现有 `ProcessExitService` 和 `NetworkIdleService` 的计时方式保持一致。
- 到点后停止自身计时器，避免重复触发。
- 使用 `Process.GetProcessesByName` 查找目标进程。
- 先调用 `CloseMainWindow()` 尝试正常关闭。
- 用 `Task.Delay` 加短轮询等待进程退出，最长等待超时秒数。
- 对剩余进程调用 `Kill()`，再尽量等待退出。
- 不在服务里触发电源动作。

### MainWindow

修改点：

- 初始化并订阅 `TimedProcessCloseService` 事件。
- `LoadSettings()` 加载自动关闭设置到 UI。
- `StartProcessTrigger_Click`：
  - 保存进程名和自动关闭设置。
  - 启动 `ProcessExitService`。
  - 如果自动关闭开启，则启动 `TimedProcessCloseService`。
- `StopProcessMonitoring`：同时停止定时关闭服务。
- UI 状态显示同时包含进程状态和自动关闭倒计时。

## 测试计划

- 构建验证：`dotnet build "AutoShutdown/AutoShutdown.csproj"`。
- 使用安全动作“锁定”验证，不真实测试关机或重启。
- 手动测试场景：
  1. 选择正在运行的测试程序，开启自动关闭，设置短倒计时，到点后程序退出并进入提醒流程。
  2. 输入带 `.exe` 的程序名，确认能归一化并监控。
  3. 程序从未出现时，到点自动关闭提示未找到，但不触发电源动作。
  4. 停止监控后，自动关闭倒计时停止。
  5. 倒计时为 0 时不能启动。
